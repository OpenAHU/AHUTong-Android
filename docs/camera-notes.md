# 聚合相机：扫码 + 笔记相机（讨论稿）

> 状态：**首版实现完成，待真机验收**（2026-10-30）。讨论期已结束，后续变更按本文档口径执行。
> 开始日期：2026-10-30

## 一、目标

把现在主页标题栏的**扫码入口**和计划中的**笔记相机**合并成一个「聚合相机」界面：同一个入口、同一块取景，用模式切换选择「扫码 / 笔记」。笔记照片按**当前正在上的课**自动归档，省掉手动选科目。

一句话定位：相机入口只留一个；扫码是瞬时动作，笔记是会话动作，靠模式区分而不是靠两个入口区分。

## 二、调研来源：学小通（Xuexiaotong）的笔记相机

用户的第一份 Android 项目，笔记相机是其中体验最好的功能。仓库本地副本：`C:\Users\InChange_Jiang\Documents\xuexiaotong-research`（shallow clone，`InChange-Jiang/Xuexiaotong@df5eee8`）。

### 2.1 它是什么

不是扫描/OCR，而是**按科目归档的课件速拍**：先选科目 → 拍 → 照片直接进该科目目录，**不写系统相册**。没有识别、没有边缘检测、没有裁剪校正。

### 2.2 操作心流

1. ProDock 右侧独立圆钮 → 相机页以「右侧滑入 + 淡入」(220ms) 覆盖全屏，退出反向滑出 (180ms)。用横向滑入表达层级，不走导航栈。
2. 拍摄页三段式：顶部 16%（关闭 / 科目胶囊）· 中间 60%（4:3 取景框）· 底部 24%（缩略图 / 双圆快门 / 镜头切换）。
3. 取景框内：双指捏合变焦（手势开始时记基准倍率，避免只能放大）、点击对焦 + 测光并弹出对焦框（250ms 进、900ms 消失）、底部居中的变焦拉杆（按住，偏移越大速度越快）。
4. 快门：0.9→0 黑色快闪 300ms 做确认；拍完不跳转、不弹确认，只把左下缩略图换成本次照片——**没有"保存到哪"这一步**。
5. 相册页（同一套全屏滑入）：按日期分组（今天 / yyyy-MM-dd），4 列网格；轻点调系统图片查看器，长按进多选（顶栏「已选 N 张 / 全选」，底部移动 / 导出 / 删除）；返回键先退多选再退页面。

### 2.3 值得照搬的实现细节

- **方向**：`OrientationEventListener` 量化到 90° → `targetRotation`；拍摄后按 `imageInfo.rotationDegrees` 旋转像素，再把 EXIF 写死 `ORIENTATION_NORMAL`（像素已正，避免查看器二次旋转）。
- **存储**：`filesDir/notes/<subjectId>/`，元数据用两份 JSON（`note_subjects.json` / `note_photos.json`）而非数据库——可读、可测、可手工修；删科目时照片落到"未分类"。
- **导出**：MediaStore 写 `Pictures/Xuexiaotong`，`IS_PENDING 1→0`，无需存储权限。
- **缩略图**：`inSampleSize` 采到最长边 256px + LruCache（堆的 1/8），缓存键带 mtime（思路接近 Luban）。
- **玻璃**：相机页 / 相册页各自 `rememberGlassBackdrop()` 独立录制——引用主页 backdrop 会折射出主页内容（全屏覆盖层用玻璃的经典坑）。
- **全屏查看**：FileProvider + `ACTION_VIEW` 交给系统查看器，翻页/缩放/平移全由系统提供。

### 2.4 它的缺口（本轮要补的）

- 无识别、无裁剪纠偏，拍照即 JPEG 95 原样存，长期体积偏大。
- 无搜索、无标签；查看依赖系统 App，不能左右滑连续翻页。
- 科目要手选——正是本轮自动归档要解决的。

## 三、已确认的设计决策

| # | 决策 | 说明 |
|---|------|------|
| D1 | **一个入口** | 沿用主页标题栏那颗钮，图标由「扫码」改为相机类图标，单击进入聚合相机 |
| D2 | **一个界面、两个模式** | 「扫码 / 笔记」，共享取景与主操作区，不拆成两个页面 |
| D3 | **模式切换位置** | 快门**下方**最底行，居中、固定不动，参照系统相机的「专业/视频/照片/人像」位置；离手势条近，导航条之外再留 12~16dp |
| D4 | **模式行形态** | 文字 + 选中高亮（系统相机式），不做厚重胶囊底；点击切换（是否保留左右滑动见 Q19） |
| D5 | **扫码模式无快门** | 切到笔记模式快门才淡入；反之淡出 |
| D6 | **底部三层结构** | 主操作行（左=缩略图/相册导入，中=快门，右=闪光灯）→ 模式行（最底、位置恒定）；主操作行在两种模式下都保持三槽高度，避免切换时整体跳动 |
| D7 | **记忆上次模式** | 只记「模式」，不记科目；退出保留，下次进入直接回到该模式 |
| D8 | **首次提示一次** | 第一次进入时说明有两个模式，不做常驻引导 |
| D9 | **切换时暂停识别** | 模式切换会解绑/重绑 use case，切换期间暂停 `ImageAnalysis`，避免误识别一次就路由走人 |
| D10 | **扫码保持现状心流** | 识别 → 260ms 确认 → 路由 → 退出；不支持的码仍出结果卡片 |
| D11 | **不照抄夸克相机** | 夸克那张图只作参考；不做满屏工具条，保持现有克制的黑底取景风格 |
| D12 | **取景框形状不变** | 横持/竖持取景框保持同一形状与比例，不因朝向重排或变形 |
| D13 | **元素各自旋转、布局完全不动** | 窗口始终锁竖屏；横持时**每个元素以自身中心为圆心**反向旋转同一角度，位置/尺寸/间距/布局完全不变。不做整层旋转，也不为横屏重排 |
| D14 | **照片方向 = 拍摄时的物理方向** | 横着拍，进竖着的相册看到的就是横的；竖着拍就是竖的。方向源与 D13 的旋转源是同一个（物理朝向），并同时驱动 `capture.targetRotation`，保证预览、界面、输出三者一致 |
| D15 | **变焦在取景框内** | 取景框底部一排变焦胶囊（1×／2×／4×，按镜头能力生成），点击跳档；**沿用现有 `ScannerZoomControls` 的语义与实现**（预设 + `clamp` + 最近档高亮），连续调节交给双指捏合；**不采纳学小通的按住拉杆** |
| D16 | **顶部极简** | 只放返回；笔记模式额外挂「科目胶囊」显示当前归档目标，点击弹出科目列表切换；扫码模式顶部右侧留空 |
| D17 | **右下槽位 = 闪光灯** | 替掉系统相机的「前后摄切换」——扫码与笔记都没有前置使用场景；语义（手电筒常亮 / 拍照闪光）见 Q17 |
| D18 | **统一竖向 3:4 取景框** | 取景框在竖屏里是 3:4（宽:高），与系统相机一致；扫码与笔记同框，扫码只改 UI，分析仍用整帧 |
| D19 | **扫码行为零改动** | 扫码的识别、变焦语义、多码选择、路由、结果卡片逻辑全部沿用现有实现，本次只动视觉 |
| D20 | **变焦上限 10×** | 笔记相机需要远距拍讲台/黑板，不止拍桌面；扫码按原有行为（现有实现怎么给就怎么给） |
| D21 | **镜头切换只靠系统** | 不做任何手动镜头切换，也不做应用层按阈值切 `CameraSelector`；只依赖 Android 11+ 逻辑相机的底层自动切换（A 方案）。若实测某些机型不达标，再单独立项，不在本轮 |
| D22 | **相册筛选用下拉列表** | 科目筛选做成下拉列表（当前科目 + 全部 + 未归档），**不做横向可滚动的筛选条** |
| D23 | **缩略图只显示图** | 网格里只有图片本身，不叠课程名/时间角标；按日期分组，每一组独占一行标题（"今天"/日期），组内 3 列换行 |
| D24 | **不提供手动旋转** | 照片按拍摄时的像素方向展示，横图在竖屏里上下留黑；不做"旋转 90°"按钮 |
| D25 | **冻结帧铺满取景框** | 结果态用 `ContentScale.Crop` 铺满 3:4，不用 `Fit`（`Fit` 会露黑边、露出下面还在动的预览） |
| D26 | **预览/分析同一视口** | 完全复用原扫码页绑定：`PreviewView(FIT_CENTER)` + `UseCaseGroup.setViewPort` + 1280×960 分析，保证冻结帧、候选码投影与所见一致 |
| D27 | **手势归 CameraX 控制器** | 捏合缩放、点击对焦交给 `LifecycleCameraController`（`setPinchToZoomEnabled`），不再与 `PreviewView` 抢触摸事件 |
| D28 | **照片方向按形状 + 物理朝向推导** | `imageInfo.rotationDegrees` 已综合传感器与 `targetRotation`，不能无脑叠加；按原图长宽比与持机方向定基础角，仅 180° 时补转，像素旋转后 EXIF 写 NORMAL |
| D29 | **查看器手势口径** | 1× 时单指不消费事件（交给 pager）；放大后单指平移、触边 0.35 阻尼、越界超 12% 宽度松手翻页并复位；双指缩放与平移同时生效；平移量必须乘 `scale` |
| D30 | **扫码方框样式** | 目标是**正方形**（边长按宽度 76% 与高度 84% 取小、居中）、四角内收；方框外 45% 黑遮罩；**取景框本身直角、不用圆角**，两种模式一致 |

### 自动归档（笔记相机的核心增量）

| # | 决策 | 说明 |
|---|------|------|
| A1 | **按当前课程自动归档** | 拍摄时读取课表当前时段命中的课程，直接归入该课程的科目目录 |

### 已采纳的默认口径（2026-10-30 第二轮，用户"按你的推荐"）

- **取景**：框宽=屏宽、垂直居中偏上；框外纯黑，不用模糊/玻璃；权限被拒与相机占用沿用现有文案。
- **手势**：捏合只在框内生效；点击对焦两模式都保留（动画沿用 250ms）；点击变焦胶囊 200ms 平滑过渡；拍照瞬间不做冻结帧，靠黑色快闪（0.9→0，300ms）。
- **模式**：模式行支持左右滑动 + 点击；切换 180ms 淡入淡出；首次进入用一次性底部气泡引导；模式记忆随账号清空，不记科目。
- **笔记归属**：科目名清掉课程名里的周次/教室后缀；同学期分开、跨学期不合并；"未归档"出现在列表且不可改名；按快门按下时刻判定；时间窗先固定 -10/+15；研究生/自定义课表不参与自动归档；同段命中多门一律未归档；元数据记录命中窗口与 auto/manual。
- **文件**：长边 2560 + JPEG 92；文件名 `时间戳_随机4位.jpg`；写盘失败 Toast 一次不弹窗。
- **相册**：按日期分组（每组一行标题）；科目筛选用**下拉列表**（全部/未归档/各课）；3 列网格、缩略图只显示图片；点击进自研 pager（左右滑 + 双指缩放）；长按多选、选中描边 + 序号角标；删除二次确认直接删；导出 `Pictures/AHUTong`，文件名不带课程名；缩略图点击进相册并定位最新；空态一个"还没有笔记"；**不做旋转按钮、按科目合并导出 PDF 留到后续**。
- **工程**：新路由 `camera`，旧 `scan` 指向同一页；旧扫码的多码浮层与结果卡/失败弹窗同步改成新视觉；相机错误只报类型与阶段不上报内容；冻结帧离开结果态立即回收；现有扫码单测必须全绿。

## 五、技术落点（开工后按此拆）

### 5.1 客户端现状（AHUTong）

- 扫码：`app/src/main/java/com/ahu/ahutong/ui/screen/scan/`（`ScanScreen` 788 行 / `QrAnalyzer` / `QrImageDecoder` / `QrRouter`），路由 `Main.kt` 的 `animatedComposable("scan")`。
- 入口：`HomeHeaderControls.kt` 的 `HomeScanButton`（36dp 玻璃圆钮，`ic_nav_scan`）。
- 课表：`feature/schedule` 的 `Schedule.kt` / `ScheduleViewModel`，含 `weekIndexes`、节假日、当前周次；课程模型 `data/model/Course`。
- 玻璃：`liquidFloatingSurface`（导航舱与标题栏控件共用）。

### 5.2 需要新增

1. `CameraScreen`：统一取景 + 模式状态 + 模式记忆（SharedPreferences），扫码分支复用现有 analyzer/router，笔记分支新增 CameraX `ImageCapture` 与归档。
2. 笔记数据层：`NoteStore`（科目 / 照片元数据，JSON 落盘）+ 缩略图缓存，参照学小通但落在 `data` 模块，目录用课程 id。
3. **自动归档判定**（纯函数，便于单测）：输入「当前时间 + 当天课程 + 周次/节假日」，输出「命中的课程 id 或 null」，含时间窗、唯一性、单双周、节假日。
4. 相册页：日期分组 + 4 列网格 + 多选（移动 / 导出 / 删除）+ 系统查看器；本轮可以先只有网格与查看，多选按需。
5. 改归档入口：长按照片 → 移动到别的科目（含"未归档"）。

### 5.3 不做的

- OCR / 边缘检测 / 透视校正 / 自动裁剪（本轮不做，作为后续候选）。
- 把笔记照片写进系统相册（保持私有，导出是显式动作）。

## 六、验证计划

- 单测：自动归档判定（时间窗前/后、多门命中、单双周、节假日、无课表）；模式记忆的读写。
