# 学习通作业 / 课程同步：调优历史、现状与刷新方案

> 状态：调研与方案，尚未实现
> 日期：2026-11-16
> 相关代码：`data/chaoxing/src/main/java/com/ahu/ahutong/data/xuexiaotong/`、`feature/xuexiaotong/`

## 0. 结论摘要

- 抓取算法只做过一次真正的调优：`8e1fd981`（作业同步节流），之后只有风控兜底，没有重写。
- **课程列表自带绝对开课时间**；**作业列表没有绝对时间**，只有状态和相对倒计时，起止时间必须进详情页拿（`ChaoxingApi.fetchWorkDeadline`）。
- 因此「按学期筛选」只能筛课程，不能筛单份作业。想按作业时间取舍，必须先抓详情。
- 现有节流对新用户不友好（只能看到未完成作业），也无法发现老师修改的截止时间。
- 切页中断不是进程被销毁，而是学习通路由被 pop 后 ViewModel 被清理、`viewModelScope` 取消。

## 1. 数据来源与约束

| 数据 | 来源 | 能否拿到绝对时间 | 备注 |
| --- | --- | --- | --- |
| 课程列表 | 学习通课程页 | 能，课程块里的「开课时间：yyyy-MM-dd～yyyy-MM-dd」 | 已解析为 `Course.endTs`（`SyncThrottle.parseCourseEndTs`） |
| 作业列表 | 课程作业列表页 | 不能，只有标题、状态、`detailUrl`、相对倒计时 | 列表解析不写 `startTs/endTs` |
| 作业起止时间 | 作业详情页 | 能，「作答时间: <em>…</em> 至 <em>…</em>」 | 每份作业一次详情请求 |
| 课程进度 | 课程学习页 | 状态类数据 | 每门课一次请求 |

关键推论：

1. **判断课程是否属于当前学期，不需要请求详情**，用课程开课时间即可。
2. **判断单份作业是否属于当前学期，必须请求详情**，否则只能看到相对倒计时。
3. 首次要展示「完整历史 + 完整时间」，就必须把所有作业详情走一遍，没有捷径。

## 2. 调优历史

### 2.1 `8e1fd981` 作业同步节流（2026-09-24）

- 解析课程开课时间，结课超过 3 天的课程整课跳过，不发请求，保留本地缓存。
- 作业详情只在「未完成且本地没有起止时间」时抓取；已完成、已有时间的作业跳过。
- 网络层与请求间隔未动。
- 新增 `SyncThrottle` 与单测。

### 2.2 风控兜底（2026-11-10，`f85ca577` + `0d2bbab5`）

- 取题命中 HTTP 202 / `antispiderShowVerify` 时抛类型化异常，错误信息带状态码与最终页。
- `get_work_detail` 增加隐藏 WebView 兜底，只取 `.questionLi`，先删答案区。
- 风控不自动重试。

## 3. 现状行为

### 3.1 作业同步（`ChaoxingApi.syncAllWorks`）

1. 每次同步先刷新课程列表。
2. 串行遍历课程：
   - 已结课课程整课跳过，复用缓存；
   - 课程之间 600ms 间隔；
   - 作业列表翻页，每页之间 800ms；
   - 只有 `SyncThrottle.needsDeadlineFetch` 为真时才进详情页，抓完 800ms 间隔；
   - 单门课程失败保留旧缓存，不中断整体同步。
3. UA 固定为 Android Chrome 91。

### 3.2 课程进度同步（`ChaoxingApi.syncCourseProgress`）

1. 每次同步先刷新课程列表。
2. **不跳过已结课课程**，所有课程串行请求学习页，每门课 800ms 间隔。
3. 单门课程失败保留旧数据。

### 3.3 同步触发

- `syncWorks` / `syncCourseProgress` 开头都会先 `silentRelogin()`，然后执行同步。
- 同步任务运行在 `XuexiaotongViewModel` 的 `viewModelScope`。

## 4. 现存问题

### 4.1 新用户观感

首次同步只抓未完成作业，历史作业列表为空，容易被误判为功能损坏。

### 4.2 老师修改截止时间

精简模式对「未完成且本地已有起止时间」的作业也跳过详情，因此改期后刷新不出来。

### 4.3 学期筛选的边界

- 只能按课程开课时间筛，不能按单份作业时间筛。
- 需要处理跨学年课程、暑期课程、补考/重修、学期切换前新课程提前出现、学期配置为空。
- 需要明确是「不抓历史」还是「不显示历史」：如果只是不抓，本地旧数据仍会显示。

### 4.4 切页中断（不是进程被销毁）

代码路径：

- `XuexiaotongScreen` 使用 `hiltViewModel()`，作用域是 `xuexiaotong` 这个 `NavBackStackEntry`。
- `syncWorks` / `syncCourseProgress` 都跑在 `viewModelScope`。
- `Main.selectPrimaryDestination` 切换一级 Tab 时执行 `popUpTo("home")`，会把学习通路由弹出返回栈。
- 路由被弹出 → ViewModel `onCleared` → `viewModelScope` 取消 → 同步协程中断。

所以：

- 切到其它 Tab 会中断同步；
- 把 App 切到后台、学习通路由还在栈里时，同步不会被 ViewModel 生命周期取消；
- 真正被系统杀进程时，才会连路由带任务一起消失，但当前现象不需要用进程死亡解释。

## 5. 目标方案

分为三层语义，避免把所有问题都压到一个「全量」开关上：

### 5.1 首次全量（每个账号一次）

- 所有课程（含历史课程）都进入同步。
- **所有作业都进详情页**，补全起止时间，包含已完成作业。
- 这是唯一能一次性拿到完整历史与完整时间的方式。
- 必须可中断、可续跑，并持久化「首次全量已完成」标记。
- 成本最高，需要进度提示与取消入口。

### 5.2 默认精简

- 课程层面：只同步开课时间覆盖当前学期的课程；历史课程整课跳过，保留缓存。
- 作业层面：
  - **所有未完成作业每次都重抓详情**，这样老师改截止时间能刷到；
  - 已完成作业不再抓详情，沿用上次全量/缓存中的时间。
- 不再使用「本地已有时间就跳过未完成作业」的规则。

### 5.3 全量刷新（用户主动触发）

- 等价于再做一次首次全量：所有课程、所有作业详情，包括已完成作业。
- 用来补历史、补老师修改过的历史时间。
- 相比常驻开关，更建议做成同步区域的显式动作；如保留开关，应放在高级选项并提示耗时与请求量。

## 6. 切页中断的修复方向

目标：同步任务不跟页面生命周期绑定。

### 方案 A：应用级同步协调器（推荐）

- 新增 Hilt `@Singleton` 的 `XuexiaotongSyncCoordinator`，持有自己的 `CoroutineScope(SupervisorJob + Dispatchers.IO)`。
- 对外暴露 `StateFlow<SyncState>`（作业/进度、当前课程、完成数、错误）。
- ViewModel 只负责触发与观察；路由被 pop 不影响同步。
- 结果由协调器写入 `Store`，回页时从状态或存储恢复进度。
- 单飞（single-flight）：同一时间只允许一个作业同步和一个进度同步。
- 账号切换/退出登录时必须取消并清理，避免旧账号任务写新账号缓存。

### 方案 B：WorkManager / 前台服务

- 需要跨进程存活或系统级后台保证时再考虑。
- 普通同步（几分钟内）用应用级作用域即可；真要防中国厂商杀进程，需要前台服务并承担通知成本。
- 不建议为了当前问题直接上 WorkManager：约束、重试策略和风控纪律都需要重新定义。

- 新账号首次同步：所有课程、所有作业（含已完成）都有起止时间，进度可见、可取消、可续跑。

## 9. 实现状态（2026-11-16）

- 同步已迁到应用级 `ChaoxingSyncServiceImpl`，切页不再取消；退出/切号时取消。
- 首次连接自动全量（当前学期），自动与手动刷新都会弹三条 toast：开始、课程列表数量、作业数量与预计时间。
- 精简模式每次重抓未完成作业详情；全量开关已加入学习通侧边抽屉（设备级持久化）。
- “本学期”不取教务学期日期，按课程**开始时间**的月份判定：2–7 月为春季学期、8 月–次年 1 月为秋季学期；2 月和 8 月本身就是寒暑假缓冲，正常教学在 3 月和 9 月开始。
- 课程进度同步同样按学期过滤并跳过已结课课程。

## 10. 首页 Hero 的作业倒计时（2026-11-17）

### 10.1 优先级（纯按时间点排序）

考试、上课、作业共用一条时间线：

1. **进行中的考试**（`start ≤ now < end`）。
2. **进行中的课**（同上；课时段内即使有作业临近截止，也先显示当前状态）。
3. **最近的未来时间点**：作业截止、下节课开始、下一场考试开始，谁先到上谁；同一分钟时作业截止优先。
4. 时间线上没有未来点：假期中 / 今日空闲。

约束：
- 已完成作业不进 Hero；**已逾期未交不上屏**；没有截止时间的作业不参与排序。
- 作业上屏固定两行：第一行“最近的作业”，第二行“还有X截止”，避免超长作业名挤掉截止时间；副标题保持“课程名 · 截止时刻”。时长超过 24 小时按“X天Y小时”表述。
- Hero 的倒计时完全由本地缓存计算，Home 每 30 秒刷新一次时钟，不触发同步。
- 点击：上屏作业时进入学习通 Tab 的“日程”子页；考试/课程/空闲仍进课程表。

### 10.2 单条静默校准（mini 抓取）

- 进入首页时，从缓存里挑「未交、有截止时间、尚未逾期、截止最早」的那一条。
- 仅当存在学习通会话且完整同步未在跑时，取一次课程密钥 + 拉该课程的作业列表（最多 3 页），找到这一条并更新状态。
- 10 分钟内最多一次；无 toast、无进度状态；失败或列表里找不到时保留缓存，不删除、不移出 Hero。
- 状态合并只覆盖状态/标题/链接与新截止时间；详情页抓到的精确起止时间优先保留。
- 更新成功会递增 `worksRevision` 并重排提醒，Hero 与学习通页同步刷新。
