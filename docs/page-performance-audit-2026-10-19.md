# 页面卡顿审查与修复（2026-10-19）

审查基线：`develop` 的 `15f6c26bf08885af55abe1726b41c6e76b4fbafd`。修复 PR：[MuxYang/AHUTong-Android#4](https://github.com/MuxYang/AHUTong-Android/pull/4)。本次重点是进入页面和主页持续运行时的主线程负担。

## 结论与证据边界

发现的核心问题不是请求本身变慢，而是 **ViewModel 构造、Compose 组合或主线程协程直接执行缓存反序列化、文件读写和图片解码**。`suspend` 与 `Mutex.withLock` 不会自动切换线程。另有成绩、账单把整个列表放在一个容器里，首次布局和后续重组都随完整数据量增长。

考试页、学习通页、预测模型存储、插件相机分别使用实际生产 Kotlin 类建立了可失败的线程探针；旧代码阻塞 UI 事件循环，修复后阻塞存储/初始化期间 UI 回调仍能执行。其他问题通过调用路径审查确认，并由完整 Android 编译、现有业务测试和新增回归测试检查兼容性。尚未在实体设备上运行帧率基准，不能承诺某机型减少多少毫秒或已消除所有卡顿。

## 已修复的问题

| 位置 | 原因 | 修复与影响 |
| --- | --- | --- |
| 主页预测：`ModelStateStore`、`JourneyModelStateStore`、`PresetModelStateStore` | suspend 方法拿锁后直接读写 AtomicFile；构造时创建目录也在调用线程 | 延迟目录初始化，模型操作在 IO 调度器中持锁执行，保留原文件格式和原子写入；文件大小统计也移到 IO |
| 全局背景、主页与编辑器图标 | 组合过程直接 BitmapFactory 解码；改变背景遮罩也使大图重新解码 | 使用后台 producer；图片修订号与遮罩修订号分开；主题取色先采样再缩放并回收中间图 |
| 主页研究生课表 | `remember` 中同步解密、解析当前课表缓存 | 后台读取，结果携带账号；缓存加载完成后再判断是否需联网，避免缓存尚未返回就重复请求 |
| 主页定时工作 | 30 秒时钟/余额刷新、5 分钟假日查询只跟组合生命周期绑定 | 同时要求主页 active 与宿主 STARTED；切页和后台停止，返回时重新启动 |
| 本科课表、成绩、考试 | 构造或主线程 launch 中同步解析缓存；成绩还同步保存排名 | 注入 IO 调度器、异步恢复；成绩网络请求等待初始缓存恢复；考试缓存及请求结果发布前校验账号；课表恢复带账号身份检查、取消旧任务，避免迟到缓存覆盖新结果 |
| 研究生课表页面 | `open()` 和 `selectTerm()` 在 UI 调用栈直接解析课表缓存 | 统一通过既有 IO 加载路径读取；保留 repository 的缓存优先和会话校验 |
| 学习通 | 构造函数读取登录态及多个 JSON 列表，还可能触发加密 Cookie 客户端初始化 | 异步恢复；恢复期间的用户操作按序执行；退出取消恢复任务，状态修订号阻止旧快照覆盖新操作；同步后的课程缓存也改为 IO |
| 学业完成度 | 页面初次加载在主线程解析缓存 | 在 IO 读取后回到主线程发布 UI 状态 |
| 失物招领 | 构造及状态切换同步读取列表缓存；校区、分类、列表的 JSON 读写位于 UI 协程 | 缓存恢复放入可取消的列表任务；大块缓存读写移到 IO；取消异常继续传播，避免把取消当网络失败 |
| 学生邮箱 | 构造时同步读取缓存概览；保存概览可能等待持久化线程所持的 monitor | 后台读取/保存；用户操作和退出使旧的初始化结果失效 |
| 成绩、账单长列表 | 在单个 LazyColumn item 内使用 Column/forEach，完整列表一次性组合 | 真正按课程/账单行使用 LazyColumn items；保留摘要、分组、空态和搜索结果 |
| 插件发现、安装、卸载 | Application/页面主线程访问 ZIP、manifest、图标、Dex、ServiceLoader | 后台发现；Java Application 使用异步入口；安装/删除与重新扫描共享同一锁；错误快照改为不可变列表 |
| 插件相机 | `ProcessCameraProvider.getInstance().get()` 可能等待初始化；照片在 main 回调解码旋转 | 仅在 Future 完成监听中取结果；关闭待初始化会话后不绑定；只解绑自身用例；后台解码后将结果回调到 main |
| 开源许可证 | 对话框组合时直接读取 asset | producer 在 IO 读取后展示 |

接口影响仅涉及内部协程入口、调度器注入与内部模型文件统计；没有改变模型文件格式、网络协议、版本号、下载源、UA 或 DoH 设置。插件相机的公开 `CameraSession` 签名保持不变；相机尚未就绪时拍照会返回可读的失败结果，用户可稍后重试。

## 主页重点核查

- 初次进入：本科课表/研究生课表缓存、全局背景图、个性化模型、插件发现均不再把上述阻塞工作放在 UI 事件循环中。
- 持续停留：时钟仍按原周期更新，余额仍按原周期刷新；停止后台定时工作后，恢复可见会重新进入刷新周期。
- 内容正确性：异步课表/成绩恢复保留缓存优先，校验账号；学习通退出后不会由旧恢复结果重新写回登录态与旧作业。
- 编辑：小组件图标后台解码；改变遮罩只更新遮罩，不重新读取背景图。天气配置在返回主页或账号改变时重新加载。
- 已有正确路径保持：二维码渲染、天气网络/定位、主 Activity 的 native SDK 初始化原本已在后台，未为了凑优化项重复改动。

## 复现与回归验证

隔离探针编译实际生产 Kotlin 类，只对 Android 环境/协作者提供最小替身。统一断言：让缓存读取或 CameraX 初始化等待受控闸门，随后向单线程 UI 队列投递回调，回调必须在闸门释放前执行。

| 实际生产路径 | 基线结果 | 修复结果 |
| --- | --- | --- |
| ExamViewModel.loadExam 缓存 | `cacheThread=page-ui`，UI 回调 false | `DefaultDispatcher-worker`，UI 回调 true |
| ModelStateStore 实际序列化 | 存储访问在 page-ui，UI 回调 false | 存储访问在 IO worker，UI 回调 true；模型文件成功写入 |
| XuexiaotongViewModel 构造 | cacheThread=page-ui，UI 回调 false | cacheThread=IO worker，UI 回调 true |
| 插件相机实际 startSession | Future 未完成时 UI 回调 false | UI 回调 true；关闭待初始化会话不绑定；解码在后台、照片结果回到 main |

新增长期回归：成绩/考试入口 JVM 线程测试、考试恢复中退出账号不发布旧缓存、学习通初始恢复期间操作按序执行，学习通入口与退出时缓存恢复竞争 JVM 测试，以及三个实际模型存储的 Android StrictMode 磁盘检测测试。Android 设备测试源加入 CI 编译检查。

本地环境没有 adb、Android SDK，未执行安装启动、实体设备 StrictMode 或 FPS 测量。Python CI 辅助测试 37 项通过，变更 whitespace 检查通过；完整 Gradle 单测、Release lint、APK 构建在 PR Actions 执行，最终结果以 PR checks 为准。

## 范围与尚需设备核实的部分

已审查 Main 路由入口、对应 ViewModel 初始化、仓库 IO 边界、主页公共内容、长列表与插件宿主。登录/设置/隐私与许可证、通知/校历、成绩/考试/课表、空教室/完成度/失物招领、天气/身份码、文档仓库/下载、账单/各类充值、邮箱/学习通均纳入源码检查；不是每一条业务分支都在设备上实际操作过。

一级页导航离场后 composition 的重新创建，还会带来首帧重组、测量及绘制录制开销；不能把本次 IO 修复视为该切页问题已根治。补充优化复用了父层已有的账号/学业权限，按插件列表与权限缓存主页小工具目录，按目录与槽位缓存可添加列表；插件异步发现后会重新读取槽位并更新图标索引。现版 SessionStore 已有内存用户缓存，重复读取它不等于每次都解密。

本次保留现有 NavHost、转场及命中测试行为。代码检查与单测不能证明首帧耗时改善幅度，仍需原设备的 atrace 基线与修复构建对照。

未发现额外明确主线程阻塞的既有路径保持原状；无法仅从源码定量评估的 GPU 模糊/材质、第三方 WebView 内容、外置插件内部逻辑、厂商系统行为仍需真机 Perfetto/帧时间验证。上述范围限制不影响已通过线程探针确认的阻塞修复，但不能将“编译/单测通过”表述为“所有机型不卡”。
